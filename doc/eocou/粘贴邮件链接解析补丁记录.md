# eocou fork：粘贴邮件链接解析补丁记录（super_editor）

更新时间：2026-05-07  
分支：eocou

## 1. 为什么要改
在 eocou 的笔记编辑器里，粘贴普通文本时，SuperEditor 默认粘贴逻辑会尝试识别 URL 和 email。某些文本会让 `linkify` 返回 `TextElement + EmailElement`，例如：

```text
Contact:somebody@gmail.com
```

历史实现只统计 `EmailElement` 数量，但取值时直接把 `extractedEmails.first` 强转成 `EmailElement`。当第一个元素实际是 `TextElement` 时，会抛出：

```text
type 'TextElement' is not a subtype of type 'EmailElement' in type cast
```

这会打断 `PasteEditorCommand`，eocou 侧再回退默认粘贴时还会再次触发同一个异常。

## 2. 触发样例（简化）
```text
Contact:somebody@gmail.com
```

SuperEditor 粘贴路径：

```text
PasteEditorCommand._findUrlSpansInText
-> tryToParseUrl(word)
-> linkify(word, EmailLinkifier)
```

预期：不崩溃，能继续粘贴；只有整段 word 就是一个 email 时，才生成 `mailto:` 链接。  
历史现象：`tryToParseUrl` 强转 `extractedEmails.first`，导致粘贴异常。

## 3. 本次改动（仅 super_editor）
### 3.1 修改文件
- `super_editor/lib/src/default_editor/default_document_editor_reactions.dart`

### 3.2 解析改动点
位置：`super_editor/lib/src/default_editor/default_document_editor_reactions.dart`

改动说明：
- 收紧 email 自动识别：只有 `linkify` 结果只有一个元素，且这个元素就是 `EmailElement`，才按 email 生成 `mailto:`。
- 不再假设 `EmailElement` 一定是结果列表第一个元素。
- 如果结果里混有 `TextElement`，说明 email 前后还有普通文本或标点，直接返回 `null`，让上层按普通文本粘贴。
- 对不含 email 的文本，不改 URL 识别路径。

### 3.3 测试说明
本 fork 补丁未新增 SuperEditor 单测。  
升级或合并冲突时，按第 5 节样例在 eocou 侧手工验证粘贴链路。

## 4. 升级上游时的冲突处理
升级 `super_editor` 时，优先关注：
- `super_editor/lib/src/default_editor/default_document_editor_reactions.dart`

处理建议：
1. 先看上游 `tryToParseUrl(...)` 是否已经不再使用 `extractedEmails.first as EmailElement`。
2. 再看上游是否把混合 `TextElement + EmailElement` 当普通文本处理，避免落到 URL 分支生成错误链接。
3. 如果上游已经覆盖上述两点，并且 eocou 侧手工粘贴样例通过，可以删除本地补丁。
4. 如果上游只调整了粘贴流程，但 `tryToParseUrl(...)` 仍可能在 `TextElement + EmailElement` 时崩溃，继续保留本补丁。

冲突判定标准：
- 若上游改法能让第 5 节样例通过，可接受上游实现。
- 若上游改法改变了 email 前缀文本的链接范围，但不会崩溃，需要按 eocou 产品表现决定是否接受。
- 若上游仍强转第一个元素，本地补丁必须保留。

## 5. 验收方式
在 eocou 笔记编辑器里粘贴：

```text
Contact:somebody@gmail.com
```

预期：
- 粘贴不抛 `TextElement` / `EmailElement` 类型转换异常。
- 内容能正常进入编辑器。
- 这种带前缀的内容按普通文本处理，不强行生成链接。

再粘贴：

```text
somebody@gmail.com
```

预期：
- 完整 email 仍可识别为 `mailto:somebody@gmail.com`。

## 6. 和 eocou 的关系（仅说明）
eocou 的 `NoteEditorPasteService` 依赖 SuperEditor 默认 `PasteEditorRequest` 来保持“按换行拆段 + URL/email 自动识别”的体验。  
本补丁修的是 SuperEditor fork 的根因，避免 eocou 业务层为了避开异常而放弃默认粘贴能力。
